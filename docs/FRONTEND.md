# Фронтенд: React, TypeScript, Tailwind и shadcn/ui

Исходники находятся в `frontend/`. Используются React 19.3.1, TypeScript 6.0.3 с `strict`, Vite 8.3.5, Tailwind CSS 4.3.3, shadcn/ui на Radix UI 1.8.1, React Router 7.18.5, TanStack Query 5.105.3 и Recharts 3.10.1. Прямые зависимости закреплены точными версиями, транзитивные — `package-lock.json`. TypeScript выбран в совместимой с ESLint версии; переход на TS 7 без обновления lint toolchain не выполняется.

Компоненты shadcn/ui добавлены официальным CLI 4.23.0 из registry `new-york-v4` и хранятся в `src/components/ui`, вместе с MIT-лицензией. Это исходники проекта: настроены локальный `cn`, плоские поверхности и `wrapperClassName` для NativeSelect. `components.json` сохраняет настройки registry. Интерфейс набран Manrope, акцентные числа тёмного варианта — Unbounded, редакционного — Playfair Display. IBM Plex Mono используется для UUID и кода. Шрифты с кириллицей и OFL-лицензиями хранятся локально, CDN для работы интерфейса не нужен. Источники новых гарнитур: [Manrope](https://github.com/google/fonts/tree/main/ofl/manrope), [Unbounded](https://github.com/google/fonts/tree/main/ofl/unbounded), [Playfair Display](https://github.com/google/fonts/tree/main/ofl/playfairdisplay).

В production Go отдаёт только скомпилированные файлы из `embed`, фронтенд обращается к тем же HTTP API. Все семь разделов, фильтры и режим предпросмотра сохранены. React Router использует hash-маршруты, поэтому ссылки вида `/#/cohorts` работают при прямом открытии. Состояние формы не зависит от пересоздания DOM при изменении высоты окна; запросами и их отменой управляет TanStack Query.

Оформление переключается кнопкой солнца / луны в шапке без перезагрузки и смены данных: `/?design=a#/overview` — тёмное, `/?design=b#/overview` — светлое редакционное. A выводит крупный LTV, доли выручки и тепловую карту продлений четырёх тарифов; B — LTV рядом с кривыми по календарным месяцам жизни цепочки и таблицу тарифов. Палитры и композиция основаны на двух предоставленных пользователем HTML-референсах; архивы и их вспомогательный runtime в репозиторий не включены. Все семь разделов используют выбранное оформление. Параметр `design` сохраняется в ссылке, а выбранный сегмент, тип доли, число периодов и preview не сбрасываются при переключении.

В интерфейсе используются короткие названия разделов, единицы измерения и фактические статусы. Рекламных заголовков, учебных пояснений и подписей сравнения макетов нет. Формулы, правила когорт и поведение хранилищ описаны в документации и Swagger. Режим предпросмотра и источник курсов остаются явно обозначены в данных.

Для графика B номер продления умножается на длительность тарифа: первое продление квартального тарифа стоит на третьем месяце, годового — на двенадцатом. Неизвестные периоды не заменяются нулями; линии прерываются на пропусках. Значения и знаменатели доступны в подсказках и с клавиатуры. Подробные расчёты продлений открываются отдельно. Сравнение UTM разворачивается в диалоге, а нажатие на источник, тариф или когорту открывает соответствующий сегмент. Показатели строятся из API без декоративных процентов роста и вымышленных записей журнала синхронизации.

`Ctrl+K` / `Cmd+K` открывает поиск по разделам со стрелками и Enter. На телефоне навигация и фильтры сворачиваются. Кнопка ссылки сохраняет параметры рабочей выборки (`from`, `to`, `plan_id`, `utm_link`, `selection`) в hash URL; полученную ссылку можно открыть в новой вкладке. Preview использует отдельный набор и не изменяет PostgreSQL; ссылка на рабочую выборку в нём отключена. Excel-отчёты и все служебные панели доступны из интерфейса.

Для разработки достаточно оставить Compose на порту 8080, затем при установленных Node 24.22.1 и npm 12.2.1 выполнить:

```sh
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`: Vite обновляет React без пересборки Go и проксирует `/api`, `/metrics`, `/status`, `/healthz` на `http://127.0.0.1:8080`. Адрес backend для dev меняется через `API_PROXY_TARGET`; это настройка dev-сервера, а не секрет, попадающий в клиентский bundle. Альтернатива без Node на хосте — `make frontend-dev`, использующий Docker и порт 5173.

Проверки и сборка из каталога `frontend/`:

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

`build` запускает TypeScript и Vite и создаёт `frontend/dist`. Fixture browser-тесты Playwright сами запускают Vite; нужен установленный Chromium (`npx playwright install chromium`). Отдельные live-тесты используют уже работающий Docker-стек без подмены API. Команды описаны в [TESTING.md](TESTING.md).

Без Node на хосте `make frontend-check` выполняет typecheck, lint, unit tests и production build в закреплённом Node Docker-образе. `make frontend-test` и `make frontend-lint` запускают соответствующие части. Linux `node_modules` из этих команд хранятся в отдельном volume и не заменяют зависимости Windows-разработки.

Для локального запуска Go со встроенным UI выполните `make frontend-build` (или Docker build с target `frontend-export`): assets экспортируются в `internal/app/web/dist`, после чего можно собирать Go. Без собранного `dist` Go-пакеты и backend-тесты компилируются; UI такого dev-бинарника отвечает 503. При обычном `docker compose up --build` эта подготовка выполняется автоматически. Генерируемые каталоги исключены из Git и Docker context, а свежий bundle копируется между Docker-стадиями.

Исходники UI находятся в `frontend/`; готовый bundle создаётся Docker-сборкой и в Git не хранится.

## Excel-отчёты

Кнопка «Excel-отчёт» открывает выбор аналитической книги (7 листов) или реестра пользователей. Выгружается вся выборка, а не текущая страница. Можно ограничить отчёт отмеченными пользователями. Поиск и фильтры применяются ко всем листам, поэтому суммы сводки сходятся с детализацией. Продления в файле относятся к участникам выгрузки; сравнение тарифов в dashboard может охватывать более широкую исходную когорту.

Книга содержит сводку, LTV по первым тарифам и каналам, lifetime-выручку по месяцу первой подписки, продления с обоими знаменателями, тепловую карту когорт и пользователей со статусом и количеством успешных оплат. Четыре диаграммы Excel связаны с ячейками. Деньги — числовые значения в RUB с форматом, Telegram ID — текст без потери точности; отсутствующие доли остаются пустыми. В реестре сохранены исходные копейки и формула пересчёта в рубли.

Генерация выполняется Go-библиотекой Excelize 2.9.1. GET `/api/reports/export.xlsx` читает подготовленные факты одного сохранённого снимка, POST — воспроизводит preview по конфигурации seed. Фронтенд передаёт `snapshot_id` и fingerprint открытого набора; удалённая версия даёт 410, несовпадение набора — 409. Другой снимок автоматически не подставляется. Для пользовательских файлов используется `private, no-store`; кеш метрик не изменяется. Одновременно формируется одна книга; отмена скачивания отменяет HTTP-контекст. Реестр записывается потоком, без загрузки всех Excel-ячеек в память. На экспорт отведено до 90 секунд; обычные API-запросы сохраняют лимит 15 секунд. Диаграммы содержат кеш подписей и значений для программ предпросмотра, сохраняя ссылки на редактируемые ячейки. Даты записаны типом Excel date в формате `yyyy-mm-dd`.
