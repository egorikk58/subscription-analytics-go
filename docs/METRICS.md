# Правила расчёта метрик

## LTV

LTV пользователя равен сумме успешных оплат за всю жизнь за вычетом полных возвратов. Неуспешные попытки дают нулевой вклад. Возврат связан с исходным платежом. RUB, BTC и USDT переводятся в копейки по сохранённой котировке оплаты. Возврат использует ту же котировку. FX в моках синтетический.

Суммы хранятся в `int64` в минорных единицах. Среднее и медиана вычисляются точно и возвращаются десятичными строками с двумя знаками. Например, `99000.00` означает 990 рублей.

Общая сводка включает пользователей без оплат. Группа LTV определяется тарифом первой подписки. После перехода на другой тариф вся выручка остаётся в первой группе. Пользователи без подписки учитываются в общей сводке.

Фильтры `from` и `to` задают UTC-диапазон `[from, to)` по дате первой подписки. Платежи выбранных пользователей учитываются за всю жизнь. `utm_link` фильтрует исходный канал привлечения.

## Продления

Для каждого тарифа берётся первая цепочка пользователя. Смена тарифа или пропуск оплаты завершает старую цепочку. Успешная оплата после неуспешной попытки относится к тому же периоду. Полный возврат убирает соответствующую оплату из цепочки.

| Поле | Правило для периода N |
|---|---|
| `eligible` | Непрерывно оплатили N периодов, N-й уже завершился |
| `renewed` | Из `eligible` оплатили следующий период |
| `rate` | `renewed / eligible` |
| `cumulative_eligible` | Из исходной когорты успели прожить N периодов, включая ушедших раньше |
| `cumulative_rate` | `renewed / cumulative_eligible` |

Например, второй квартал оплатили и завершили 239 человек. Из них 175 оплатили третий квартал. Условная доля — 73,2%. Если шесть месяцев с начала квартальной цепочки успели пройти у 356 человек исходной когорты, кумулятивная доля — 49,2%. При нулевом знаменателе API возвращает `null`.

Кварталы отсчитываются от старта цепочки конкретного пользователя. Матрица группирует людей по календарному месяцу их первой подписки. Границы периода сохраняют день старта и ограничиваются последним днём месяца. Для месячного тарифа 31 января → конец февраля → 31 марта.

Для зрелости используется `dataset.observed_through`, а `data_as_of` обозначает время снимка. На статических моках граница наблюдений совпадает с концом истории seed. Более позднее фактическое событие может сдвинуть её.

Маршруты, параметры и примеры доступны в Swagger по `/docs/`. В списке выберите «API аналитики» и используйте **Try it out**. Контракты моков показывают внутренние Docker-адреса.
